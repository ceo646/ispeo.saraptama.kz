# Анализатор коммерческой недвижимости krisha.kz

Инструмент находит **самые выгодные коммерческие помещения для покупки под сдачу
в аренду** по данным [krisha.kz](https://krisha.kz). Логика: сопоставляет
объявления о **продаже** коммерции с рынком **аренды** в тех же районах, считает
доходность/окупаемость/дисконт к рынку и выдаёт **топ-20** объектов в виде
HTML-отчёта.

По умолчанию настроен на **Астану**, цену покупки **до 100 млн ₸**, с
**исключением цокольных и подвальных** помещений.

---

## ⚠️ Важно: где запускать

krisha.kz стоит за Cloudflare и **блокирует запросы из дата-центров/облака и CI**
(в т.ч. из среды Claude Code — там хост вообще закрыт egress-политикой). Поэтому
**живой скрапинг нужно запускать с обычного интернета в Казахстане** — с вашего
ноутбука или локального VPS. Для проверки самого инструмента без сети есть режим
`--demo` на синтетических данных.

---

## Установка

```bash
cd commercial-analyzer
python3 -m venv .venv && source .venv/bin/activate   # опционально
pip install -r requirements.txt
```

## Запуск

```bash
# Реальный прогон (нужен доступ к krisha.kz):
python -m analyzer --config config.yaml

# Offline-демонстрация формата отчёта (без сети):
python -m analyzer --demo --out report/demo.html
```

Результат — `report/top20.html` (или путь из `--out`). Откройте в браузере.

## Как считается «самое выгодное» (композитный скор)

1. **Бенчмарк аренды по районам.** Из объявлений *аренды* коммерции берём
   медианную ставку **₸/м²/мес** по каждому району (Есиль, Алматы, Сарыарка,
   Байконур, Нура). Если по району мало данных — подмешиваем городскую медиану и
   снижаем «достоверность».
2. **Метрики по каждому помещению на продажу:**
   - ожидаемая аренда = площадь × ставка района;
   - **доходность** = аренда × 12 / цена покупки (валовая, годовая);
   - **окупаемость** = 1 / доходности (лет);
   - **дисконт к рынку** = насколько цена за м² ниже медианы района.
3. **Композитный скор (0–100)** — нормализованная сумма с весами
   (настраиваются в `config.yaml`):

   | компонент      | вес по умолчанию | смысл |
   |----------------|------------------|-------|
   | доходность     | `0.5`            | чем выше аренда к цене — тем лучше |
   | дисконт к рынку| `0.3`            | «недооценённые» по цене за м² |
   | достоверность  | `0.2`            | насколько бенчмарк аренды подтверждён данными |

### Фильтры (config.yaml)
- цена ≤ `deal.price_to` (по умолчанию 100 млн ₸);
- площадь в диапазоне `deal.area_from … area_to`;
- `filters.exclude_basement: true` — выкидываем всё, где в этаже/типе/заголовке
  встречается «цоколь», «подвал», «полуподвал», «-1 этаж» и т.п.;
- отсекаются аномальные доходности (ошибки в данных) вне
  `min/max_plausible_yield`.

## Структура

```
commercial-analyzer/
├── analyzer/
│   ├── __main__.py     # CLI: scrape → analyze → report
│   ├── config.py       # конфиг + карта городов/районов + построение URL krisha
│   ├── scraper.py      # HTTP, пагинация, вежливые паузы, ретраи
│   ├── parse.py        # разбор HTML krisha (все CSS-селекторы собраны здесь)
│   ├── analyze.py      # бенчмарки, метрики, композитный скор, топ-N
│   ├── report.py       # генерация HTML-отчёта
│   ├── models.py       # модели Listing / ScoredDeal
│   └── demo.py         # синтетические данные для offline-прогона
├── config.yaml
├── requirements.txt
└── report/             # сюда пишется отчёт (demo.html — пример)
```

## Настройка под другой город

В `config.yaml` поменяйте `city` (`almaty`, `shymkent`, …). Список районов для
распознавания задан в `analyzer/config.py → CITY_DISTRICTS` — при необходимости
дополните.

## Если krisha поменяет вёрстку

Все CSS-селекторы разбора собраны в одном файле — `analyzer/parse.py`. Если
парсинг перестанет находить поля, правьте селекторы там (структура кода не
меняется).

## Оговорки

- Доходность **валовая**: без налогов, простоя, коммуналки, ремонта и комиссий.
  Это ранжирующая оценка, а не бизнес-план — каждый объект проверяйте вручную.
- Оценка аренды опирается на медиану района; для нетипичных объектов (склад vs
  ритейл на 1-й линии) реальная ставка может отличаться.
- Соблюдайте `robots.txt` и условия krisha.kz; держите умеренную частоту
  запросов (`scrape.request_delay`).
